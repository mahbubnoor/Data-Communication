Why switching?

  • Connecting every pair directly (a mesh) needs n(n − 1)/2 links: impractical beyond a few devices
  • A switched network is a set of interconnected nodes called switches
  • Switches create temporary connections between devices attached to them
  • End systems (computers, phones) attach to switches; switches attach to each other

Circuit switching

  • Switches are joined by links, each divided into channels by FDM or TDM
  • A connection is a dedicated path: one channel on each link
  • Resources are reserved at setup and held until teardown
  • Data is a continuous flow, not packets; switches forward by channel, so no addresses are needed

The three phases of a circuit

  • Setup: the end systems' addresses are used once, to build the path
  • Data transfer: data flows with no addressing, no waiting at switches
  • Teardown: either side signals the end; switches free the channels
  • Total delay = setup + data transfer + teardown

Circuit switching: efficiency and delay

  • Efficiency: low; resources stay reserved for the whole connection, busy or idle
  • Fine for steady voice calls; wasteful for bursty computer traffic
  • Delay: after setup, minimal and constant; no waiting at switches
  • Worked example: a 30 kbit message over 3 links at 1 Mbps

Packet switching: datagram networks

  • The message is divided into packets; each carries the destination address
  • Each packet (a datagram) is routed independently
  • Packets may take different paths, so they can arrive out of order, or be lost
  • No setup or teardown: also called connectionless; used by IP in the Internet

Routing tables in a datagram network

  • Each switch has a routing table: destination address → output port
  • Tables are built and updated by routing protocols (network-layer topic)
  • On arrival, the switch reads the destination address and looks up the port
  • The forwarding decision is made packet by packet

Delay in a datagram network

  • No setup delay, but each switch must receive the whole packet before forwarding it (store-and-forward)
  • Each packet may also wait in a switch's queue
  • For one packet over 3 links: 3 transmissions + 3 propagations + 2 waits
  • Delay varies from packet to packet: not uniform

Virtual-circuit networks

  • A cross between circuit-switched and datagram networks
  • A path is set up first; then all packets of the connection follow it, in order
  • Packets carry a short local label, the VCI, not the full destination address
  • Normally at the data link layer: Frame Relay and ATM (today, MPLS works similarly)

Virtual-circuit identifier (VCI): a small number with meaning on one link only; carried in every frame

Data transfer: following the VCI through the tables

  • Switch 2: (1, 66) → (2, 22); switch 3: (2, 22) → (3, 77)
  • The lookup is a simple table index, so switching is fast

Setting up and tearing down a virtual circuit

  • Setup has two steps: a setup request and an acknowledgement
  • The request uses global addresses and fills three of the four table columns
  • The acknowledgement carries back each next-hop VCI to fill the fourth
  • Teardown removes the rows; the VCIs can be reused

1 · Setup request (A → B)

Travels by the global address. Each switch picks the out port, fills in port, in VCI, out port, and chooses an unused incoming VCI for the next link.

2 · Acknowledgement (B → A)

Travels back; each switch learns the out VCI chosen by the next switch, completing its row. A learns VCI 14.

3 · Teardown

A sends a teardown request; B confirms; every switch deletes the row.

Virtual circuits: efficiency and delay

  • Pays a setup delay, like circuit switching, and teardown at the end
  • Data transfer is store-and-forward, like datagram switching
  • If resources are reserved at setup, delay is the same for every packet
  • Switching is fast: one table lookup per frame, no route calculation

Inside a circuit switch: the crossbar

  • A space-division switch keeps paths physically separate
  • A crossbar connects n inputs to m outputs with n × m crosspoints
  • Closing crosspoint (i, j) connects input i to output j; each input uses one at a time
  • Problem: crosspoints grow as n², and most are idle at any moment

Multistage switches and Example 8.3

  • Combine small crossbars in stages; inputs can reach outputs through several middle crossbars
  • Stage 1: N/n crossbars of size n × k; stage 2: k crossbars of N/n × N/n; stage 3: N/n of k × n
  • Ex. 8.3: a 200 × 200 switch with n = 20, k = 4 needs only 2,000 crosspoints
  • Drawback: blocking: with only 4 middle paths per group, a 5th call from a group cannot connect

Time-division switches, and inside a packet switch

  • A time-division switch reorders TDM slots instead of building separate paths
  • The TSI uses memory: write in arrival order, read out in the order of the destinations
  • Large exchanges combine stages: TST (time–space–time)
  • A packet switch (router) has input ports, a switching fabric, output ports and a routing processor

Time-slot interchange (TSI)

Writes incoming TDM slots into RAM in arrival order, then reads them out in the order the outputs need: here A moves to slot 2, C to slot 1 …

Key takeaways

  • Switches create temporary connections, avoiding n(n − 1)/2 direct links
  • Circuit: setup, data, teardown; reserved channels; constant delay but wasteful
  • Datagram: independent packets with full addresses; efficient; variable delay and order
  • Virtual circuit: setup, then label-swapped packets (VCI) on one path
  • Crossbar n² crosspoints; multistage 2kN + k(N/n)²; Clos k = 2n − 1 never blocks
