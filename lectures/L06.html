Data elements and signal elements

  • A data element is the smallest piece of information: one bit
  • A signal element is the shortest unit of a digital signal: one level held for a time
  • r = number of data elements carried by each signal element
  • r = 1 (NRZ), r = 1/2 (Manchester), r = 2 (2B1Q), r = 4/3 (8B6T)

1 bit → 1 element (NRZ) · r = 1

1 bit → 2 elements (Manchester) · r = 1/2

2 bits → 1 element (2B1Q) · r = 2

8 bits → 6 elements (8B6T) · r = 4/3

Three levels: 3⁶ = 729 patterns carry 2⁸ = 256 data values

Bit rate, signal rate and bandwidth

  • Bit rate N: data elements per second (bps)
  • Signal rate S (baud rate, pulse rate): signal elements per second (baud)
  • Fewer signal elements per second need less bandwidth: we want S small
  • The case factor c depends on the data pattern (all 1s, alternating, random)

S = c × N × (1 / r) baud

Bmin ≈ S

Nmax = (1 / c) × B × r

N = bit rate (bps) · S = signal rate (baud) · c = case factor: 1 worst, 1/2 average, 0 best

Worked example: N = 100 kbps, r = 1, average case c = 1/2

Three problems a good line code must solve

  • Baseline wander: the receiver compares each level with a running average; long runs drag the average
  • DC component: a non-zero average voltage; many channels block very low frequencies
  • Self-synchronisation: the signal itself must keep the receiver's clock in step
  • Also wanted: built-in error detection, noise immunity and low complexity

Baseline wander: the receiver's running average (dashed) drifts during long runs

Worked example: why self-synchronisation matters

  • Problem: the receiver's clock runs 0.1% faster than the sender's
  • At 1 kbps the receiver samples 1,001 times per second: 1 extra bit each second
  • At 1 Mbps it samples 1,001,000 times: 1,000 extra bits each second
  • Transitions in the signal let the receiver correct its clock before errors pile up

1 kbps link, receiver clock 0.1% fast

1,000 × 1.001 = 1,001 bits counted per second

1 extra bit/s

1 Mbps link, same clock error

1,000,000 × 1.001 = 1,001,000

1,000 extra bits/s

The faster the link, the more damage the same clock error does, so high-speed codes must self-synchronise.

Unipolar NRZ: the simplest code

  • All signal levels are on one side of zero: 1 = +V, 0 = 0 V
  • NRZ (non-return-to-zero): the level is held for the whole bit
  • Costly: it uses twice the power of polar NRZ for the same noise immunity
  • Rarely used today; it is the code we used at the end of Lecture 5

Polar NRZ: NRZ-L and NRZ-I

  • NRZ-L (level): the voltage level itself gives the bit; in Forouzan, 0 = positive, 1 = negative
  • NRZ-I (invert): a 1 inverts the level at the start of the bit; a 0 leaves it unchanged
  • Polar levels ±V can average to zero, but long runs still create DC and wander
  • NRZ-I survives a polarity swap in the cable, because only changes carry information

Return-to-zero (RZ)

  • The signal goes to zero in the middle of every bit
  • 1 = positive for the first half; 0 = negative for the first half
  • The mid-bit return gives a transition in every bit: self-synchronising
  • Cost: two signal changes per bit, three levels, more bandwidth; largely replaced by Manchester

Biphase: Manchester and differential Manchester

  • Manchester = RZ's mid-bit transition + NRZ-L's two levels
  • In Forouzan: 0 = high-to-low in mid-bit, 1 = low-to-high
  • Differential Manchester = RZ + NRZ-I: always a mid-bit flip; an extra flip at the start for 0, none for 1
  • Used in 10 Mbps Ethernet (Manchester) and Token Ring (differential Manchester)

Bipolar: AMI and pseudoternary

  • Three levels: positive, zero and negative
  • AMI (alternate mark inversion): 0 = zero; each 1 is the opposite polarity of the previous 1
  • Pseudoternary: the roles swap: 1 = zero, 0s alternate
  • Alternating pulses cancel, so there is no DC component; a broken rule signals an error
  • Used on T1 lines; long runs of 0s need scrambling (B8ZS, HDB3)

Multilevel coding: 2B1Q

  • Multilevel (mBnL) schemes map m bits onto n signal elements with L levels, keeping 2ᵐ ≤ Lⁿ
  • 2B1Q: 2 binary bits → 1 quaternary (four-level) signal element
  • Data rate is twice NRZ-L's for the same baud rate
  • Used in ISDN and early DSL on telephone lines

More multilevel codes: 8B6T and 4D-PAM5

8B6T

8 binary bits → 6 ternary (three-level: +, 0, −) signal elements

3⁶ = 729 patterns for 2⁸ = 256 data values: 473 spare patterns for synchronisation and error detection

DC balance: if two weight-+1 patterns come in a row, the second is inverted

Average S ≈ 3N/4 · used in 100BASE-T4 Ethernet

4D-PAM5

Five levels (−2 … +2) sent over four wire pairs at once (four dimensions)

8 bits travel as one group of 4 parallel symbols; level 0 used for error correction

1 Gbps over four pairs at 125 Mbaud each

S = N/8 per pair · used in 1000BASE-T Gigabit Ethernet

Multitransition: MLT-3

  • Three levels (+V, 0, −V) and a cycling rule
  • A 1 means move to the next level in the cycle; a 0 means stay
  • Worst case (all 1s): one full cycle per 4 bits, so the signal behaves like a wave at N/4
  • Used with 4B/5B in 100BASE-TX Fast Ethernet over Cat 5

Block coding: adding redundancy on purpose

  • mB/nB: replace each m-bit group with an n-bit code (n > m)
  • There are 2ⁿ codes but only 2ᵐ are used, so we pick the ones with good properties
  • Goals: guarantee enough 1s (transitions) and detect invalid codes as errors
  • Block coding comes before line coding: it changes bits into bits

Then a line code carries the coded stream: e.g. 4B/5B + NRZ-I, or 4B/5B + MLT-3.

4B/5B: the code behind Fast Ethernet

  • Each 4-bit group becomes a 5-bit code from the table
  • No code has more than one leading 0 or more than two trailing 0s
  • So the coded stream never contains more than three 0s in a row
  • 100 Mbps data → 125 Mbps on the line (25% more), then NRZ-I or MLT-3

8B/10B: better balance for faster links

  • 8-bit bytes become 10-bit codes: 1,024 patterns for 256 bytes
  • Each code has at most one more 1 than 0, or vice versa
  • The encoder alternates between two versions of a code to keep the long-run balance at zero
  • Detects many errors: invalid codes or a wrong disparity
Property8B/10B
Groups8 bits → 10 bits (internally 5B/6B + 3B/4B)
DC balancecodes chosen with equal or nearly equal 0s and 1s
Running disparitytracks whether more 1s or 0s were sent; picks the code that balances
Run lengthnever more than five identical bits
Used inGigabit Ethernet over fibre, PCI Express 1 and 2, USB 3.0, SATA

Same 25% overhead as 4B/5B, but better DC balance and error detection. Newer links use 64B/66B or 128B/130B to cut overhead.

Scrambling with HDB3

  • HDB3 (high-density bipolar 3-zero) allows at most three 0s in a row
  • Every four consecutive 0s are replaced by 000V or B00V
  • The choice depends on how many non-zero pulses were sent since the last substitution
  • Used with AMI on E1 lines (Europe and most of Asia)

Key takeaways

  • Signal rate S = c × N / r; bandwidth follows S, so we want few signal elements per bit
  • Good line codes avoid baseline wander and DC and keep the receiver in sync
  • NRZ is cheap but flat on long runs; Manchester syncs every bit but doubles bandwidth
  • AMI removes DC; multilevel codes (2B1Q, 8B6T, 4D-PAM5) cut the baud rate
  • Block codes (4B/5B, 8B/10B) and scrambling (B8ZS, HDB3) remove long runs of 0s
