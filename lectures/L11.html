Byte stuffing (character-oriented)

  • Add a special escape byte (ESC) before any data byte that looks like a FLAG
  • An ESC in the data is also escaped (ESC ESC)
  • Receiver: on ESC, delete it and treat the next byte as plain data
  • Cost: frame grows by one byte per stuffed byte
  • Used in PPP (Lecture 12)

Bit stuffing (bit-oriented)

  • Flag = 01111110: six 1s in a row
  • Sender: after five consecutive 1s in the data, insert a 0
  • The data can then never contain six 1s, so it never looks like a flag
  • Receiver: after five 1s, if the next bit is 0, remove it
  • The 0 is stuffed even if the next data bit is already 0

Types of errors

  • Single-bit error: only one bit of the data unit changes
  • Burst error: two or more bits change
  • Burst length: first corrupted bit to last corrupted bit
  • Bursts are far more likely: noise lasts longer than one bit
  • The higher the rate, the more bits one noise spike hits

Redundancy: detection or correction

  • To find errors, send redundant bits along with the data
  • Detection: only ask whether an error happened
  • Correction: also find the wrong bits and how many (much harder)
  • Correction needs more redundancy; it suits links where resending is slow (space, broadcast)
  • Coding arithmetic is modulo 2: addition = subtraction = XOR

Detection

Is there an error? Yes/no. Then discard and ask again (retransmission, ARQ).

Correction

Which bits are wrong? Fix them at the receiver: forward error correction (FEC).

Modulo-2 arithmetic

Add and subtract are the same: XOR. No carries.

Block coding

  • Split the message into k-bit datawords
  • Add r redundant bits: n-bit codewords, n = k + r
  • Only 2k of the 2n possible n-bit words are valid
  • Receiving an invalid codeword reveals an error
  • An error that turns one valid codeword into another valid one is not detected

Hamming distance

  • d(x, y): number of positions where two words differ
  • Compute it as: XOR the words, count the 1s
  • Between sent and received word: the number of bit errors
  • Minimum Hamming distance dmin: smallest distance between any two valid codewords
  • dmin decides how many errors a code can detect or correct

How many errors? The dmin rules

  • To detect s errors: dmin ≥ s + 1
  • s errors move a codeword only distance s away: it cannot reach another valid one
  • To correct t errors: dmin ≥ 2t + 1
  • Then the received word is still closer to the original than to any other
  • Ex. 10.1 code: dmin = 2 → detects 1, corrects 0

Simple parity check: C(5, 4)

  • Add one bit so the total number of 1s is even
  • Receiver recomputes the parity: the syndrome
  • Syndrome 0: accept; syndrome 1: discard
  • Detects any odd number of errors
  • Misses any even number: dmin = 2

Two-dimensional parity

  • Arrange data in a table; add a parity bit to every row and every column
  • Sends the extra parity row with the data
  • Detects all 1-, 2- and 3-bit errors and most bursts
  • Can even locate and correct a single error (row × column)
  • Misses 4 errors forming a rectangle

Hamming code (7, 4): encoding

  • Corrects any single-bit error: dmin = 3
  • Choose r ≥ 3, then n = 2r − 1, k = n − r: here n = 7, k = 4
  • Condition: 2r ≥ k + r + 1 (every error position plus “no error” needs its own pattern)
  • Each check bit is the parity of a different set of three data bits
  • Syllabus topic; in Forouzan 4th ed. (10.3), not in the 5th

Hamming (7, 4): decoding with the syndrome

  • Receiver recomputes the three checks over the received bits
  • The 3-bit syndrome names the wrong bit (table)
  • Flip it back: single errors are corrected
  • Two errors give a wrong syndrome: miscorrection ✗
  • Old-slide fix: row 3 received must be 1101010, not 1101000

Cyclic redundancy check: the encoder

  • Sender and receiver agree on a generator (divisor) of r + 1 bits
  • Append r zeros to the dataword
  • Divide using modulo-2 (XOR, no borrows)
  • Leftmost bit 0? Use 0000 instead of the divisor
  • Replace the zeros with the remainder: that is the codeword

CRC: the decoder

  • Receiver divides the whole received codeword by the same generator
  • No zeros are added
  • The remainder is the syndrome
  • Syndrome all 0s: accept, the dataword is the first k bits
  • Otherwise: discard (an error is detected)

CRC with polynomials

  • Write a bit pattern as a polynomial with coefficients 0 or 1
  • Generator 1011 = x³ + x + 1, degree 3 → 3-bit CRC
  • Codeword c(x) is a multiple of g(x); error e(x) is missed only if g(x) divides e(x)
  • Standard generators are chosen to catch all common errors
  • Bursts longer than r: caught with probability ≈ 1 − (1/2)r

1011 = x³ + x + 1

1001 = x³ + 1

Checksum: add instead of divide

  • Sender adds all data words; sends the complement of the sum
  • Uses one's-complement arithmetic: carries wrap round and are added back
  • Receiver adds everything including the checksum and complements
  • Result 0: accept; anything else: discard
  • Simple, fast in software; used by IP, TCP and UDP

The Internet checksum (16-bit)

  • Data split into 16-bit words (4 hex digits)
  • Checksum field set to 0, then all words added in one's complement
  • Carries beyond 16 bits are added back to the sum
  • Checksum = complement of the sum
  • Example text “Forouzan”: checksum 7038

Key takeaways

  • Frames need boundaries: flags plus byte stuffing (ESC) or bit stuffing (0 after five 1s)
  • Errors are single-bit or bursts; bursts are common
  • Detect s errors: dmin = s + 1; correct t: dmin = 2t + 1
  • Parity detects odd errors; Hamming (7,4) corrects one using the syndrome
  • CRC: modulo-2 division, remainder appended; checksum: one's-complement sum
